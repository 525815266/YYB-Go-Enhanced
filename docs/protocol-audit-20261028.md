# 应用宝协议修复复核（2026-10-28）

结论：v0.2.36 的短链兜底更新有帮助，但不能据此认定近期的全部账号异常已经解决。首次隔离测试证明部分账号存在可用的取码、续期路径；后续生产复测仍有上游凭据拒绝，不代表持续恢复。旧登录票据被拒绝与部分账号的上游凭据异常需要分别处理。

2026-10-29 补充：v0.2.37 / v0.2.38 的构建发布已恢复，飞牛 v0.2.38 已部署；真实生产取码仍未全部通过。部署前备份与宿主机同凭据对照、v0.2.39 的诊断修补见[生产复测记录](native-keepalive-audit-20261028.md#2026-10-29-生产复测与后续修补)。

后续在用户登录官方客户端后，进一步还原了定时续期策略，并通过官方检查接口确认 ID 1 的旧 refresh token 被上游以 `40030` 拒绝，详见 [官方客户端续期复核](native-keepalive-audit-20261028.md)。

## 复核对象与范围

- GitHub v0.2.36 源码，以及短链补丁前的 v0.2.35 源码。
- 飞牛实际运行的 `yyb-go` 容器。运行二进制包含新增的四个短链地址，容器健康；镜像版本标签仍为 0.2.35，不能仅据版本标签判定补丁是否存在。
- 本机应用宝主程序 5.10.7600.6722；另外找到实际协议运行库 `WmpfRuntime/5.10.7300.414/runtime/ilink2.dll`。应用主程序版本不等于协议运行库版本。
- 账号与会话测试采用生产数据库的私有临时快照，不将测试失败状态写回生产。只对一个可用账号执行了一次成功的真实续期，并以原凭据比较条件安全保存轮换结果。测试未执行商户签到、兑换或预约。

| 账号 2、9，重新取登录票据后取 code | 均成功，返回非空的 32 字符 code | 原加密、握手和 JSAPI 取码存在完整可用路径 |
| v0.2.35 / v0.2.36 使用同一份新票据对照 | 账号 2、9 均成功 | 在当前 HTTPDNS 正常的飞牛环境中，旧版也能走通；不能把新地址补丁视为全部根因修复 |

没有修改协议版本号、密钥或签名算法来猜测恢复。静态文件确认主程序中仍存在同一 hostAppID、设备标识与签名常量；完整取码和单账号续期是更直接的运行证据。未逐项反汇编证明所有协议常量与客户端一致，也没有验证长期或 30 天持续保活。

## 本次候选修补

1. 登录响应先读取基础业务错误码，以 `ManualAuthRejectedError` 保留上游拒绝，避免误判为响应格式变化。
2. 对已实测的 `-10` 登录拒绝，先沿账号配置的出口获取新登录票据，再尝试原请求一次。拒绝发生在发送 JSAPI 操作之前；不通过重放已执行的业务操作进行恢复。
3. 新票据仅用于建立由会话池保存的替换会话，不旋转 token、不修改扫码时间或凭据到期时间。取票据遇到网络错误时保留原始诊断，不立即续期。
4. 后续恢复失败同时保留原协议错误、取票据错误和续期错误，避免只显示最后一个 `RC_PARAMS_INVALID`。
5. 对齐源码与 Docker 默认版本到 VERSION；后续以 v0.2.37 发布，并补齐 Docker 构建上下文规则。

已增加业务拒绝、正常响应、旧票据恢复、失败诊断、网络错误和代理出口回归测试。Windows 全量 `go test ./...` 通过；飞牛 Linux 的相关协议 / HTTP 回归通过，Linux 主程序编译成功。飞牛私有快照的完整 `/wxapp/getCode` 请求在候选修补下返回 HTTP 200、非空 code。未验证 macOS / ARM 运行或完整 Release 产物矩阵。

本节记录最初的候选验证。随后用户授权推送，以 v0.2.37 发布该修补并恢复原生 Release；v0.2.38 进一步实施官方刷新路径与两阶段保存，最新实测见[官方客户端续期对照](native-keepalive-audit-20261028.md#v0237--v0238-实施与再验证)。没有批量修改正常/失效账号状态。无法用代码从已被上游拒绝的凭据恢复授权；需要重新授权后分别验证取码与续期。
