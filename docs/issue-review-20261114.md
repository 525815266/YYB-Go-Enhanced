# 2026-11-14 issue 复核

本轮以 `main` 的 `v0.3.6`（`4fe2c07`）为基线复核开放 issue，并完成 Docker 发布和飞牛部署。只把能够由代码、构建或脱敏运行结果确认的内容写成修复；上游拒绝、授权撤销和长期保活没有用重试伪装成已解决。

## 已修复并验收

- **#167 镜像标签**：主分支构建现在同时发布 `VERSION` 对应的镜像标签；补跑了缺失的 `0.3.5` 镜像构建。GHCR 目前可拉取 `0.3.4`、`0.3.5`、`0.3.6` 和 `latest`。`0.3.5` 的镜像摘要为 `sha256:ba5b3bd78f31f20e5db4dd2ab94ad380d93886bd6d51dda4cf66d25d9fc2ac08`，`0.3.6/latest` 为 `sha256:940ff08ea6e6da3f3aeccb7e37b994281526fcc87eed9f7797034e7868e00027`。
- **#167 的持续 `-14`**：健康成员优先调度已在 `0066250` 合入，账号组按 `alive → unknown → session_only → expired` 选择成员，同一类内保持 LRU；单个成员被上游拒绝时不会继续黏着它。该改动缓解本地成员选择问题，但不能解除微信侧账号／AppID 风控锁定、登录预算或恢复退避，因此“等待约一小时后恢复”不能被本地代码确认成已修复。
- **飞牛部署**：以 `0.3.6` 精确 digest 部署，隔离启动、版本／提交校验、健康检查通过；28 个账号身份、归属、fleet 分组、管理员库和原容器配置保持不变，部署前备份及回滚镜像均已保存。此次没有发送业务取码或恢复请求。

## 保持开放的边界

- **#168 永久保活**：refresh token 被微信撤销后只能重新授权；现有代码不能保证永久有效，也没有 30 天自然保活证据。
- **#165**：脚本已修复固定 `xcxData`、未验证缓存和失败后继续执行的问题；仍需要使用者配置本人数据并做真实飞天会员验收。YYB code 不能单独证明能换出会员 token。
- **#142**：缓存 UIN 精度和请求布局已有回归修复，仍缺报告者在同一 Docker／Windows 条件下的新版脱敏验收；不凭旧版差异宣称已经完全解决。
- **#141/#158**：H5 设备字段、组件参数、重复发送和失败阶段诊断已有修复；报告中的具体外层 `-14` 或 `AppData decrypt/parse failed` 尚未有同条件新版样本，不能继续重放授权来“验证”。
- **#136**：`-12028`／空 code 仍可能是微信账号或目标 AppID 的上游业务拒绝；本地临时名单已改为有限期、按主账号组统计且成功可解除，不把单个失败目标全局拉黑。
- **#138**：QQ 浏览器已有独立扫码链路；渠道 2/5 未找到完整签发流程，雷电长期恢复与手游助手被上游拒绝的场景仍未证明，不能把短期取码写成长期保活。
- **#35/#36/#32/#146**：分别是协议诊断深搜、第二面板／双变量同步、自定义变量名及业务脚本需求；现有材料不足以安全合入，暂不改变默认行为。
