# 代理与账号保活

YYB Go Enhanced 的代理按微信账号独立保存。默认扫码、OAuth 回调、凭据刷新、用户资料、`wx.login`、LongLink 和 ShortLink 均遵循该账号的代理策略；v0.2.29 起可单独指定小程序调用直连。

## 账号代理与脚本代理的区别

控制台代理只影响 YYB 服务发出的协议请求，不接管青龙 Python/JavaScript 脚本向活动网站发出的业务 HTTP 请求。服务端收到的是账号引用、AppID 和协议参数，不能据此可靠判断脚本文件名。

因此 `PERMIT_API`、`DY_PROXY` 等其他脚本的代理白名单变量并非 YYB 平台配置。需要“仅部分脚本走代理”时，应在对应脚本或面板的单任务环境中配置其支持的代理功能。不要为此反复切换同一账号的全局代理，也不要遇到关键词就自动重放领取、兑换或提交类请求，以免重复执行。

此处的脚本白名单与代理供应商要求的服务器出口 IP 白名单是两回事。

## 代理模式

| 模式 | 适用场景 | 是否适合保活 |
| --- | --- | --- |
| 直连 | 服务器出口可用且账号地区不敏感 | 是 |
| 静态代理 | 长期稳定的固定 HTTP/SOCKS5 出口 | 是 |
| 动态代理 API | 按次提取的短效 IP | 否，只适合扫码或临时请求 |
| 品赞配置 | 集中保存 `core-extract` 链接并按账号选择省市 | 取决于代理有效期；短效套餐否 |
| 巨量配置 | 按业务编号、API Key 和地区动态提取 | 取决于代理有效期；短效套餐否 |

账号显式选择直连后，会覆盖全局 `-tcp-proxy`。账号显式代理不可用时，请求直接失败，不会静默回退为直连。

## 静态代理格式

支持常见写法：

```text
host:port
user:pass@host:port
host:port:user:pass
host:port|user|pass
```

协议可选择 HTTP CONNECT 或 SOCKS5，两者均支持用户名密码认证。

## 保活走代理，小程序调用直连

在「代理设置」选择账号，保留原来的静态代理或配置库，再把「小程序调用出口」设为「直连」并保存即可。

| 请求 | 跟随账号连接模式（默认） | 小程序调用直连 |
| --- | --- | --- |
| 取码、手机号、`operateWxData` 及其兼容入口 | 账号代理 | 服务器直接连接微信 |
| 扫码、用户资料、后台/手动保活 | 账号代理 | 账号代理 |
| 小程序调用失败后的凭据恢复 | 账号代理 | 账号代理 |
| 青龙脚本请求商家业务接口 | 由脚本自行决定 | 由脚本自行决定 |

此设置是主动分流，不是代理故障后的自动回退。直连调用不会额外提取动态代理；如果需要刷新凭据且原账号代理仍不可达，请求仍会失败，不会改走直连刷新。短效动态代理仍不参与后台保活。两种出口也不保证账号更稳定，请按实际网络验证。

`GET /accounts/proxy?ref=账号标识` 返回 `protocol_proxy_mode`；`PUT /accounts/proxy` 在原有代理配置中可传 `"protocol_proxy_mode":"direct"` 或 `"account"`。未传该字段时保留原值，新账号及旧库默认 `account`。重扫、配置复制和 ID 整理保留此设置。「测试代理」只检测所配置代理，不代表小程序直连链路已验证。

## 动态代理 API

填写完整的 HTTP/HTTPS 提取地址，地区和运营商参数保留在 URL 查询参数中。解析器支持：

- `txt`：纯文本 `host:port` 或带认证信息的代理；
- `json`、`json2`：常见对象和列表结构；
- `data`、`result`、`list`、`proxy_list`、`rows`、`items` 等嵌套字段；
- 分开的 IP、端口、用户名和密码字段。

动态代理会短时间复用，避免一个脚本流程内反复提取和跳 IP。短效代理有效期应覆盖一次完整请求链；一分钟套餐适合短任务，但不等于适合后台保活。

## 品赞

代理配置库可保存多个命名的品赞链接，例如“山东套餐”或“移动出口”。账号只关联配置项和省市；修改链接后，关联账号统一生效。

两种常见鉴权方式：

- 账号密码：推荐使用 JSON，读取品赞返回的临时 `account` 和 `password`，不依赖服务器公网 IP。
- 出口 IP 白名单：服务器公网出口必须已加入供应商白名单。

提取成功但连接失败时，先检查返回的代理是否需要认证、服务器出口是否在白名单、协议选择是否正确，以及短效 IP 是否已经过期。不要只看提取接口返回 `200`。

## 巨量

配置库保存企业动态代理的业务编号和 API Key。系统按账号省市生成签名，并读取 `json2` 返回的临时 `http_user`、`http_pass`。也可使用自动白名单模式。

供应商提取入口可能只支持 HTTP。是否启用应结合本机网络、反向代理和安全要求判断，不要把含签名的提取 URL 写入公开日志。

## 地区匹配

账号添加页和代理设置页可推荐省市：

- HTTPS 页面可在用户授权后读取浏览器位置，再进行反向地理解析。
- 局域网 HTTP 页面无法读取手机 GPS，只能根据公网出口估算。
- 推荐结果只负责预填，不会自动覆盖已有账号配置。
- 代理测试会分别显示供应商入口和实际出口；入口机房所在地不代表最终出口地区。

同一账号重新扫码只更新凭据并恢复状态，不会把已有代理、地区和提前刷新时间重置为直连。

## 自动保活

<a id="scan-first-call-409"></a>

### 扫码成功后首次调用返回 409（#105 / #109）

确认扫码并成功入库，只能证明取得过凭据；需要结合首次失败的实际业务码判断后续是否被上游拒绝。v0.2.40 起，协议恢复失败的 409 保留原 `code` / `msg`，增加安全诊断，例如：

```json
{
  "code": 409,
  "msg": "account login_buffer expired (refresh failed); re-scan required",
  "data": {
    "rescan_required": true,
    "upstream_errors": [
      {"stage": "manual_auth", "upstream_code": -10},
      {"stage": "login_buffer", "upstream_code": -101},
      {"stage": "check_login", "upstream_code": -109, "wechat_code": 42007}
    ]
  }
}
```

这是格式示例，不代表所有 409 都是该错误链。`manual_auth` 是协议握手拒绝，`login_buffer` 是获取登录票据，`refresh_token` 是凭据刷新，`check_login` 是官方登录检查。仅返回已解析的数字业务码；不回显 token、OpenID、代理认证或原始响应。本次 `/accounts/refresh`、批量刷新和集成刷新结果遇到业务拒绝也增加 `upstream_errors`。

v0.2.45 增加 `shortlink_application` / `shortlink_transport`：短连接经过 MMTLS 认证后，wpkg 头返回应用或传输拒绝码，且没有加密业务正文。实际已观察到 `shortlink_application / -14`；不能仅据这个数字解释成 OAuth 撤销。即使后续会话重建被 ManualAuth 拒绝，首次短连接码也保留在错误链；不改变既有重建次数和账号清理条件。

v0.2.43 进一步保留主刷新与后续 check-login 的两段错误类型。v0.2.40–v0.2.42 这一路径可能只显示 `check_login`，不能据此认为没有执行主刷新。只有真正收到的业务拒绝才列入诊断；网络超时仍按网络异常处理，不猜测微信码。

首次恢复失败还会写入默认服务日志，使用固定字段与账号数字 ID。账号已经标为失效后，再调用只返回 409 与空诊断列表，不重新请求上游；服务没有持久保存历史拒绝码，事后单独调用 `/accounts/refresh` 或手动状态接口无法还原旧原因，请保留首次 409 的诊断或对应时间的服务日志。不能从“同地区家宽”、健康接口 200 或本地剩余两小时推断凭据仍有效。

普通扫码的 `/qr/{sid}/cancel` 仅移除二维码会话，不撤销已入库账号。项目未设置失效后重扫的冷却期；同一微信重扫沿用原账号记录，但上游是否接受新授权仍以真实调用结果为准。不要把缺少具体错误的 409 直接归因于代理或风控。

### 默认配置

默认配置：

```dotenv
YYB_KEEPALIVE_INTERVAL=2m
YYB_KEEPALIVE_AHEAD=4m
```

行为如下：

- 每两分钟执行一次轻量数据库检查，检查本身不会提取代理。
- 直连账号在 access token 剩余不足 4 分钟时刷新，对齐已复核的应用宝客户端默认策略。已有环境变量、启动参数和每账号代理刷新窗口仍优先生效，升级不会偷偷覆盖自定义值。
- 配置专属代理的账号默认在剩余不足 5 分钟时刷新，可按账号调整为 5 到 90 分钟。
- 短效动态代理标记为不参与长期保活，避免后台反复提取 IP。
- 将 `YYB_KEEPALIVE_INTERVAL=0` 可关闭后台保活。

扫码来自官方主登录 `/pc_yyb/pcyyb_oauth` 的凭据，续期使用对应的 `/pc_yyb/pcyyb_refresh_token` 和 `pc_yyb` 签名；标明 `pc_yyb_auth` 来源的独立 wxapp 授权保留 `_auth` 路径。主登录续期出现含糊的 `-109` 时，最多额外检查一次官方 check-login，以其返回的完整凭据或明确错误为准，不把 `invalid login type` 直接解释为微信已撤销账号。

后台续期先保存 token，不额外获取 ILink 登录票据。实际调用需要时才取票据；取票据失败或浏览器取消请求不会丢掉已经成功轮换的 token。并发重扫、删除、整理 ID 或手动标失效后，旧刷新请求不能覆盖新账号状态。

网络超时、DNS、代理故障等临时错误会保留账号状态并在后续重试；只有微信明确拒绝 refresh token，或凭据已经确定失效，才标记为需要重扫并停止协议调用。这些处理不保证上游长期接受授权。

### 约两小时后失效的排查（#96）

默认 access token 有效期通常为 7200 秒，约两小时；它与扫码授权的长期窗口不是同一个计时。约两小时出错不能直接证明是异地登录，也不保证换同城代理就会恢复。先区分凭据到期、刷新请求失败和微信明确拒绝刷新凭据。

v0.2.33 收紧失效判定：代理或 HTTP/JSON 错误中的“token 过期”不再触发永久失效；微信业务响应只报告 access token 过期，或未明确是哪类 token 时，也保留重试。现有 access token 尚有效则保留原状态；已到期则显示“待确认”，后台仍可重试。只有协议端明确拒绝 refresh token、要求重新登录、已知 `42007` / `40188 invalid scope` 拒绝，或本地缺少 refresh token，才停止保活并要求重扫。业务响应与传输错误按类型区分，不再只检查整段错误文本。

这一修正不会自动恢复旧版已经标为失效的账号，也不能证明 #96 的具体网络与授权问题已解决。排查请提供：

- 实际显示“待确认”还是“已失效”，以及刷新时的完整脱敏错误；
- 程序版本、Docker / 原生 / Magisk 部署方式；
- 直连 / 静态代理 / 动态短效代理，后台保活是否开启、提前刷新时间；
- 出错前后日志中的刷新结果，不要只提供扫码后时长。

短效动态代理不参与后台保活；若关闭保活或刷新出口持续不可达，access token 到期仍会影响调用。不要公开真实 token、OpenID、login_buffer、二维码或代理密码，也无需在缺少错误依据时反复重扫。

## 保活成功但 getcode 超时

凭据保活主要使用 HTTP 请求，小程序 `getcode` 还需要建立协议 LongLink/ShortLink 隧道。普通 HTTPS 代理测试或保活成功，不能单独证明这些目标 IP、端口和协议链路都可达，也不能仅凭超时判断账号已经失效。

v0.2.25 修复 SOCKS5 / HTTP CONNECT 在 TCP 连接成功后，握手读取未及时响应调用上下文取消的问题：握手使用调用截止时间与连接超时中的较短者，完成后释放取消回调并清除临时截止时间。HTTP 传输层另设 30 秒连接及握手等待上限，防止连接复用机制保留的后台拨号无限等待。代理选择及直连回退策略不变。

排查时请提供版本、Docker/原生/Magisk 环境、代理类型、从请求开始到报错的时长，以及脱敏完整错误：

- `dial proxy failed`：连接代理入口失败。
- `socks5/http-connect proxy handshake to ... failed`：代理认证或建立目标隧道失败，可结合目标与错误判断。
- 后续 LongLink/ShortLink 超时：需要继续检查目标连通性和协议响应，不能用加长超时保证成功。

请勿公开代理密码、提取密钥、协议令牌或账号凭据。某个 issue 的实际根因仍需结合其日志确认。

v0.2.28 修正 LongLink 候选回退：同一 IP 的不同端口独立保留，优先尝试上游提供的 443；最多六个候选共享剩余登录预算，每个候选有独立时限，失败即关闭连接。HTTPDNS 查询最多占用默认 8 秒，给官方域名回退留出时间。原先首个候选可能用完默认 30 秒登录预算，后续端点尚未尝试就返回 `LongLink login cancelled`；现在错误会包含候选序号、端点及失败阶段。

v0.2.31 补齐另一种情况（#93）：HTTPDNS 返回节点不代表这些节点在当前出口可达。最多六个候选始终为 `longcloud.weixin.com:443` 预留最后一个位置；前面节点全部失败后，仍能尝试系统 DNS 或当前代理解析出的官方地址。回退仍使用该账号的小程序调用出口，不会越过代理策略偷偷直连；每个候选继续共享原总时限。

失败信息现在列出所有已尝试节点的端点和阶段。不要只看最后一个 IP：`dial tcp ... timeout` 是 TCP 建连失败，`LongLink handshake ...` 是协议握手失败；单纯 TCP 80/443 可连也不等于 MMTLS 握手或账号登录成功。从 Docker 主机测通时，还需在 YYB 容器的实际网络中对照。

此改动不能让不可达的代理变得可用。#76 已由反馈者确认更换代理后恢复；#84 反馈者已确认“代理保活 + 小程序调用直连”持续数天在线，但原代理取码问题仍需独立定位。保活成功、同市 IP 或单条超时信息都不足以判断根因。

### Nginx 504 与协议超时（#76 后续）

`504 Gateway Time-out` 的 HTML 页面说明某层 Nginx 等待上游超时；它不是微信明确返回的账号失效结果，也不能单凭页面确认是哪层代理。关闭 SOCKS5 后正常，说明故障与代理路径有关，仍需区分代理可达性、目标协议连通性和服务端等待处理。

v0.2.26 进一步修复代理握手**之后**的处理：LongLink、ShortLink 和 HTTPDNS 读写响应请求取消及整体截止时间；同账号协议登录、凭据刷新和动态代理提取的排队等待可取消。小程序调用默认共用 `RequestTimeout + 35 秒` 的预算（默认 43 秒）。可识别的网络错误、超时和 EOF 直接保留原始诊断，不再因此清除会话、强制刷新凭据或重复调用。

更新后，优先在可信内网直达 `http://宿主机:映射端口` 请求相同接口，与域名反代结果对比；配置了协议 token 时继续携带原有鉴权。需要同步提供容器版本、请求耗时和同一时刻的 `docker logs --since 10m yyb-go` 脱敏错误。只延长 Nginx 的 `proxy_read_timeout` 不能修复不可达的 SOCKS5 或微信协议链路。

## refresh token 生命周期

微信可能只更新 access token，而不轮换 refresh token。后台保活不能保证 refresh token 永久有效。

控制台会记录 refresh token 的首次观察时间，并在长期未轮换时提示“建议重扫”。这是提前预警，不等于账号已经失效；只有微信实际拒绝凭据时才进入失效状态。重新扫码同一账号会更新原记录，并保留其代理与业务配置。

## 安全注意事项

- 代理 API URL、认证信息和账号关联关系保存在本机协议 SQLite 数据库。
- 不要把代理数据库、提取 URL、白名单密钥或账号密码提交到 GitHub。
- 代理测试应同时验证提取成功、隧道连通和出口地区。
- 需要稳定保活时优先使用直连或长期固定出口，不要依赖一分钟短效代理。
