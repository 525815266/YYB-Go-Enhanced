# QQ 浏览器独立授权验收（2026-11-08，v0.2.94）

QQ 渠道现在直接在 YYB 扫码页授权，由服务端换票、取码和保存刷新凭据，不需要安装官方 QQ 浏览器、扩展或手动推送。此前 v0.2.93 的扩展链可用，但本次用独立授权替代日常导入操作。身份、token、code、设备值、票据及原始响应均不公开。

## 失败原因与对照

官方浏览器普通登录页只申请 `snsapi_login`。直接照搬这个 scope，微信扫码和原生 `WXAuth` 均成功，但小游戏票据接口返回 `10002`。浏览器已有 ctk 的小游戏链能工作，并不证明普通登录权限的新授权也足够。

| 隔离对照 | 结果 |
| --- | --- |
| 浏览器已签发 ctk，省略机器 ID、GUID 和设备头 | 换票成功 |
| 新独立授权，仅普通登录权限 | WXAuth 成功，换票 10002 |
| 同一普通权限凭据，补已有真实原生设备参数 | 仍 10002 |
| 同一普通权限凭据，按官方 GetQbid 补账号映射 | 映射成功，仍 10002 |
| 新独立授权，`snsapi_login,snsapi_runtime_pcsdk` | WXAuth、换票、实际取码成功 |

该对照支持缺小游戏权限是本次独立换票失败的关键差异，不把 10002 泛化为任何场景都只有一个原因。补权限需要新的用户确认，不能靠本地修改旧 token。没有重放已消费的 OAuth code。

## 服务端链路

1. `/qr` 为 QQ appid 生成两种权限的二维码，每次随机 state。
2. 确认后请求 `pbprxpc.qq.com` 的 `trpc.mtt.wx_auth.wx_auth/WXAuth`，取社会 access token、refresh token、上游 expire 和 unionid。
3. 调用 `GetWxLoginBuffer`，验证票据属于 QQ 宿主，再交共享 ILink 栈。
4. 同渠道后续后台调度走原生 `RefreshToken`，保持身份绑定，将旋转凭据先保存，再进行后续恢复；后台刷新不额外换小游戏票据。

PBProxy 使用四字节大端总长度加 protobuf 信封。社会微信 refresh token 与 `Qbtoken` 账号 token 不互换。仅使用上游访问期限，没有给 QQ 自造一天、七天或三十天；上游没有期限时不安排猜测性后台刷新。换票失败后的二维码重试复用已取得凭据，不重放成功的 WXAuth。

原生 unionid 随凭据持久化，公共多渠道链接继续按原机制核验，不允许缺失或不一致的身份合并。旧扩展导入仍可用，但不能从 ctk 推导 refresh token；需要独立重扫获得新链，升级本身不会自动改旧授权。独立扫码后应停用原扩展推送；服务端也在数据库事务内拒绝用 ctk-only 导入覆盖该账号，保留原刷新凭据与授权资料。

## 真实验收与限制

以下均为独立回环实例和独立数据库，不触碰正式 ID1／ID22。时间为北京时间：

| 时间 | 验收 | 结果 |
| --- | --- | --- |
| 17:23 左右 | 用户确认补充小游戏权限的独立二维码 | 换票并保存成功 |
| 17:24:17 | 第一次实际 wx.login | HTTP 200，32 位 code，建立数据库会话 |
| 17:24:32 | `/accounts/refresh` 存活检查 | 新鲜凭据未刷新，不当作续期证据 |
| 17:25:24 | 单次原生 RefreshToken，保存到独立库，再用返回凭据换票 | 两步成功，上游 expire 7200 秒；本次 access／refresh 不变 |
| 17:25:42 | 刷新后的实际取码 | HTTP 200，32 位 code |
| 17:25:44 | 停止并重启隔离服务，从 SQLite 重载后取码 | HTTP 200，32 位 code |

原生刷新验收由本地隔离 harness 调用生产同一协议客户端与数据库 CAS 保存；后台定时调度和保存顺序另有合成测试覆盖。没有修改真实到期时间来制造跨期限样本。token 相同、返回 7200 秒和计时延长均不证明长期服务器授权寿命。跨真实期限、数日存活、服务端撤销后的恢复仍待观察，不宣称 30 天保活已解决。

桌面微信快捷确认已接通服务端参数和回调解析，使用 QQ 渠道及随机 state，回调只允许固定官方 HTTPS 地址。启用 `YYB_ENABLE_PC_LOGIN` 后显示入口；需要使用访问页面电脑上的微信。合成回归覆盖渠道绑定、重复 state／code、错误地址和重复消费，真实桌面微信快捷确认尚未验收。

## 回归覆盖

- 原生帧、路由、字段类型、错误脱敏、token 旋转、身份绑定与缺期限处理。
- OAuth runtime scope、随机 state、票据失败重试不重放 OAuth。
- QQ 后台按真实期限刷新、无期限不猜测刷新、旧桥接继续跳过、先保存凭据且不额外取业务票据。
- 社会凭据、unionid、真实期限从 JSON／SQLite 重载，界面不套通用 30 天总寿命。
- 隔离桌面／390px 手机页面的单渠道与多渠道 QR 请求，不调用扩展推送；公共链接共享渠道清单。

雷电、手游助手的持久化研究及渠道 2/5 不因 QQ 这次验收而自动视为解决。相关历史边界见[渠道登录与持久化复核](channel-login-persistence-20261108.md)。
