# 控制台与账号管理

本文汇总 Web 控制台里的账号工作台、扫码渠道、多渠道账号、账号合并、接口测试、运行日志和更新入口。部署与配置见[根 README](../README.md) 和[配置与账号安全](configuration.md)。

## 账号工作台

工作台支持昵称、备注、ID、OpenID 搜索和状态筛选。v0.2.22 使用紧凑卡片网格，电脑端可在卡片内直接更新扫码、管理代理；手机以单列卡片展示，选中账号后在其下方显示快捷操作。点击“待确认”可确认账号状态，新增账号和新增链接位于顶部。账号区随数量自然展开，已失效账号停止展示有效期倒计时。页面预览使用虚构账号。

## 扫码渠道：YYB 与 PCMgr

v0.2.48 支持 YYB / PCMgr 两套扫码渠道，Linux / Docker / Windows 均使用纯 Go 实现，无需安装或常驻原客户端。“个人设置 → 扫码渠道”可设置个人默认，管理员可设置系统默认，优先级为本次手选 > 个人默认 > 系统默认。更新链接及扫码页可临时切换，先说明影响并确认，扫码成功后替换原 ID 的授权，保留代理、归属、任务和推送设置，不新增账号 ID。

同渠道更新仍核对原 OpenID；跨渠道身份标识不同，无法仅凭 OpenID 自动证明是同一微信，请使用原微信扫码。若新身份已属于其他账号，拒绝替换。平台管理的面板变量自动迁移旧 OpenID 引用，数字 ID 引用保持不变；面板暂不可用时保留迁移记录，重新同步可重试。手动维护的外部 OpenID 引用需自行更新。

卡片右上角 logo 区分渠道。YYB 展示凭据与扫码周期两条进度，PCMgr 展示“下次续期”计划，不把它当成真实有效期。纯 Go 主动轮换、取新票据及小程序取码已通过本地实测；v0.2.49 完成新扫码后的飞牛 API 复测，长期自然续期仍未验证，详见[双路径实现与验证边界](pcmgr-local-lab-20261029.md)。

## 多渠道账号：一个微信，多个渠道

同一个微信在 YYB、PCMgr、GameAssist 各扫一次，会得到几条账号记录（各有自己的 ID）。把它们合并成一个多渠道账号（编队，v0.2.76 起的调度能力）后，脚本只需要用主账号：请求在各渠道之间轮换，某个渠道被上游拒绝时自动转到其他渠道，脚本不用改。合并前会核对微信 unionid，不是同一个微信的账号会被拒绝。

**一次扫出多个渠道：** 扫码页顶部的“多渠道扫码”开关打开后，每个渠道显示一个二维码，用同一个微信依次扫。每扫完一个就自动并进同一个多渠道账号，第一个扫到的是主账号（扫到的账号已经在某个多渠道账号里时，以那个账号为准）。扫码页显示各渠道的进度和合并结果；开关记在浏览器里，也可以用 `/scan?multi=1` 直接进入。渠道清单来自服务端（`GET /api/scan-channels`），以后新增渠道，二维码、卡片和设置页会自己出现。

**给已有账号补扫：** 账号卡片和“调用配置”里的“多渠道扫码”按钮打开 `/scan?ref=<主账号 ID>`。已有的渠道显示“已绑定 ID x”（需要重扫的会高亮重扫按钮），没有的渠道出二维码，扫到的自动并进这个账号。

**卡片：** 多渠道账号只占一张卡片：每个渠道一个图标，图标上的小点表示状态（绿色可用、红色已失效、黄色建议重扫或需补授权），右上角是“2/3 可用”这样的汇总，需要处理的渠道直接写在卡片上。服务端已有、你还没绑定的渠道显示为虚线的“+”，点一下去补扫。“渠道详情”展开后每个渠道一行：ID、状态、有效期、更新、代理、移出；点这一行选中该渠道的账号（接口测试用它）。“拆分多渠道账号”把它们恢复成各自独立的账号，不删除任何账号。

**合并已经分开的几个 ID：** 账号区的“合并渠道”按钮：选主账号，勾选要并入的独立账号（昵称相同、渠道不同的会预先勾选），点合并。结果逐个显示；unionid 不一致的会被拒绝，确认确实是同一个微信时可以点“仍然合并”。已经在别的多渠道账号里的账号不能直接并入，先移出或拆分。它和上面的“合并账号”不同：“合并账号”修复误新增的重复记录，把来源的授权移入保留的 ID 并删除来源 ID；“合并渠道”不删除任何账号，随时可以拆分。

**面板里只放主账号：** 同步到面板（`YYB_SERVER`）时，多渠道账号只列主账号；同步成员账号等于同步它的主账号，“同步全部账号”跳过成员。多渠道扫码时，服务端在扫码确认约 15 秒后才同步面板，那时账号已经合并，面板里只会出现主账号，没合并的账号按自己同步。之前手动加进面板的成员条目不会被自动删除，请自行移除，否则脚本会按每个 ID 各跑一遍。

**增加一个渠道需要什么：** 在 `internal/qr/channels.go` 的清单里加一项，并补齐它的 OAuth 地址、账号识别（`Public()` 里按 OpenID 前缀或凭据里的 `provider` 判断 `scan_product`）、`resource/static/images/scan-<Badge>.png` 徽标，以及 `resource/static/js/scan-channel.js` 里同一项的内置副本（公开的一次性链接页读不了登录后的 `/api/scan-channels`；两处不一致时测试会失败）。

接口：`POST /api/fleet/bind-many`（主账号 + 多个成员，逐个返回结果）、`POST /api/fleet/dissolve`（拆分）、单个绑定与解绑仍是 `POST` / `DELETE /api/fleet`。两个归属不同的账号不能编在一起。界面测试见 `tests/multi-channel-ui.cjs`，需要先用 `tests/seed-multi-channel-ui.py` 往隔离实例里放虚构账号。

## 合并账号

误从“新增账号”录入了另一条记录时，可在账号区点击“合并账号”，选择来源与保留 ID，预览后确认。原 ID 的代理、归属、备注、任务和推送保留，来源授权移入后释放来源 ID。仅允许同一归属下合并；来源不可用或已有专属任务时先处理再合并，避免遗留指向旧 ID 的任务。系统不能自动证明跨渠道是同一微信，需自行核对两条记录。

## 接口测试

接口测试按能力分组并显示当前 YYB / PCMgr 渠道，展开“测试命令”可复制跟随访问地址、账号和参数的 Bash / PowerShell 示例；服务端自动判断渠道，无需改已有脚本路由。示例只引用环境变量，不填入页面中的真实令牌。（v0.2.50；详见[反馈复核与验证范围](issue-review-20261029.md)。）

## 运行日志

v0.2.53 在管理员左侧新增“运行日志”，支持分类、等级、账号、渠道和时间筛选，可查看续期、票据、原生恢复及调用的独立事件。日志重启保留，近 7 天最多 10,000 条，不采集密钥或请求正文。

**掉线事件里的 `recent`（v0.2.74 起）：** 账号被上游拒绝时，`account.expired`（授权失效）和 `account.refresh_failed`（按需或手动刷新失败）事件的详情里带一个 `recent` 列表，写着这个账号刚刚做了什么：最近 3 分钟内最多 12 条取码、取号、转发请求，每条有 AppID、请求类型（`op`）、结果（`event`：`succeeded`、`failed`、`recovery_started`、`recovered`、`circuit_deferred` 等）、距离这条事件多少秒（`age_s`），以及失败时的上游拒绝码（`code`，例如 `-14`）。只含标识符，不含请求内容、凭据或 code；只在内存里记着，重启后清空。反馈“账号掉线”时，请把这一条事件的详情贴出来，它能直接说明掉线前最后几个 AppID 是什么。

## 皮肤

控制台右上角的“皮肤”按钮可在“经典”和“清爽”之间切换。经典是原来的深色侧栏界面，默认使用，界面不变；清爽是白色侧栏、蓝色主色、胶囊状态徽标的浅色界面，已失效账号不再闪烁和盖章。选择只保存在当前浏览器，不影响接口、账号数据和其他用户。清爽皮肤的样式集中在 `resource/static/css/skin-clean.css`，全部限定在 `html[data-skin="clean"]` 之下，不会改动经典界面。

## 检查更新

管理员可点击控制台顶栏版本号检查新版本。系统会识别当前运行环境：Windows、Linux、macOS 裸机提供匹配架构的 Release 下载，Magisk 提供模块 ZIP；Docker 仅在维护执行器已连接时提供在线更新和重启。

v0.2.24 根据 #74 的反馈，增加仅供版本检查使用的 `YYB_UPDATE_PROXY` 和可选的 `YYB_UPDATE_VERSION_URL`，并修复前端过早取消备用查询的问题。默认仍使用官方 Raw / API / Release 来源，不内置第三方镜像。遇到连接重置或 403，请按[更新网络排错](maintenance.md#检查更新报连接重置或-http-403issue-74)检查容器到宿主机代理的可达性；Docker 拉取镜像使用宿主机的独立网络配置。感谢 @Xx1aoy1 提供 Armbian 实测排查过程。

完整版本变化见 [CHANGELOG.md](../CHANGELOG.md)；管理员更新与重启的完整说明见[系统维护](maintenance.md)。
