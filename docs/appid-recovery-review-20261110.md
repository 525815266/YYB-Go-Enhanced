# 自动 AppID 限制复核与恢复（v0.3.3）

重复空码不能证明 AppID 是公众号、网站应用或已下线小程序。旧实现将跨账号空码永久持久化，缺少恢复入口；WPS 在本次单项复核后重新正常返回 code，证实长期误拦确实存在。

## 已修复

- 保留现有空码阈值，失败仅在 15 分钟窗口内累计；跨账号阈值改按主账号组计数，同一微信的多个渠道不能当作独立证据。单账号部署累计 4 次仍可暂缓请求。
- 达阈值只限制 15 分钟。到期后由一个正常业务调用复核；同 AppID 并发调用在本地等待下一次机会，避免同时集中复测。没有后台主动取码任务。
- 小程序取码成功清除该项及计数，解除结果持久化。再次空码延后 15 分钟。账号过期、限速、熔断、网络错误及明确业务拒绝不延长 AppID 空码限制。
- 历史名单保留并迁移为有限期限，重启不顺延已有时间。管理员明确放行、环境白名单在运行时及重启后都优先；放行项不再被重新学习。面板放行原先没有覆盖动态名单的问题已修正。
- 临时拒绝保持 HTTP 403 兼容，增加 `data.temporary`、`data.retry_after` 及 `Retry-After`。设置页显示复核时间、是否正在复核，支持解除单项。
- H5 不使用小程序的空码名单；不会把所有失败自动改成 H5，不会猜公众号回调。内置网站应用限制和管理员明确拒绝继续有效。

## 真实复核方法

逐项保留原规则和意图记录，先确认控制小程序可用，再使用正常主账号入口做单次真实取码。失败时在同账号执行一个已知可用小程序作对照；两者都失败的项目不能归因于 AppID，最多改用另一个已验证的主账号确认一次。不批量运行签到、抽奖、购物、浇水等业务写操作。原始响应、code、账号身份和日志只保留在私有目录。

本次开始时动态名单为 87 项，另有 2 项内置限制、1 项管理员明确限制。内置及管理员名单不属于自动学习名单。拼多多公众号使用实际 H5 入口复核，不能拿小程序取码失败当作它不可用的证明。

## 2026-11-10 真实结果

87 项均已按实际接口完成复核：

| 分类 | 数量 | 结果 |
| --- | ---: | --- |
| 小程序首次复核成功 | 84 | HTTP 200，32 位 code，已逐项解除旧学习限制 |
| 首次账号侧失败、独立主账号复核成功 | 2 | 原请求及同账号控制均为 `jslogin_business -13000`；换已验证正常的主账号组后均 HTTP 200、32 位 code，没有重新拉黑 |
| 拼多多公众号 | 1 | `/wx/h5code` HTTP 200、32 位 code；实际果园回调与随机 state 匹配，未访问业务回调 |

两项账号侧失败分别是 `wx1ddeb67115f30d1a`（海底捞）与 `wx2823161452551c9e`（电玩城门店）。这证明它们在本次其他有效授权上可用，不表示最初失败账号的上游限制已经解除。

飞牛 86 项小程序恢复结果已回读：没有仍被动态名单拦截的成功项，没有新增自动项。原 2 项内置、1 项管理员明确拒绝及 11 项允许规则保持。剩余 1 项历史学习记录是拼多多公众号，不影响已成功的 H5；不拿它重新测试 `wx.login`，不把 H5 成功冒充小程序成功。升级后该历史记录也只保留有限复核期限。

全部 87 项都能在现有青龙脚本中映射到实际使用处；其中多项来自同一个多门店脚本，不能仅凭陌生 AppID 判为公众号。复核期间先后有一次控制失败和上述两项账号侧失败，均保留原始证据，没有隐去或无限重试。

验证包括 Go 全量测试、vet、临时限制与白名单专项回归，以及 1280 / 390 宽设置页单项解除和无横向溢出验收；Linux CI 增加 AppID 并发 race 检查。本机缺少 race 所需 C 工具链，没有把本地普通测试称为 race 通过。

真实成功仅证明当前授权和指定接口可返回 code，不代表目标业务登录、全部任务或长期保活都通过。未批量运行签到、抽奖、购物或浇水。私有目录保留开始规则、逐项意图、控制请求、原始响应和脱敏汇总；公开明细只含 AppID、接口、HTTP 状态和 code 长度，不含 code 本身或账号资料。
