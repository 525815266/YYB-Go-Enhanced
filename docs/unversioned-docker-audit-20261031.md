# 未标版本号的早期 Docker：追溯与独立验证

2026-10-31，收到“早期未标版本号的 Docker 可以自动续期”的反馈，并取得两张界面截图。以下区分历史代码、故障注入验证和本次真实样本；短时取码成功不作为长期续期成功。

## 两套 UI 对应什么阶段

- 顶部为“YYB Go 控制台 / 账号、扫码、能力调用集中操作”、右侧“服务正常 / Swagger / 扫码添加”的界面，在 2026-07-30 首个公开提交中已经存在。7 月 31 日加入后台保活时保留这套 UI。
- 左侧为“我的控制台 / 我的微信账号 / 添加账号”、含“已激活短链接”，扫码页提示 `YYB_ENABLE_PC_LOGIN=true` 的界面属于后续平台 UI。短链接菜单于 9 月 8 日加入，控制台显示构建版本的改动于 9 月 18 日加入；截图特征可收窄到这一阶段，不能仅凭截图认定某个精确镜像。
- 本次选用 7 月 31 日首次加入后台保活的完整源码，源提交 `24a1ae892b96912b09aa76ee8ef346c75ffbde66`。同时对照控制台显示版本之前的 `219e05da0cd5ad0dfb9cc6829cc90da1c8edebcb`；后者虽已有 Magisk 版本说明，控制台尚未显示版本，不能将“页面没有版本号”当成所有产物都没有版本。

两阶段的 `ilink.go`、MMTLS 协议和加密源码无差异。UI 已变化，但这几份核心协议实现没有随 UI 更换。

## 离线验证

历史源码的现有 HTTP、协议、QR 和存储包测试通过。额外审计测试仅留在隔离源码副本，未加入部署程序，使用虚构响应验证：

1. 旧版确实构造带签名的 `_auth` 刷新请求。
2. 两小时未到期、没有协议缓存时，首个业务调用仍会强制刷新凭据。
3. 返回相同 token、缺少 `expires_in` 时，旧版会默认增加本地期限，不能据倒计时断言服务端续期。
4. 虚构的字符串拒绝码和看似有效的 `user_info` 可被旧解析器当作成功。这个合成用例不表示真实服务端发过这种响应。

## 本次独立 Docker 样本

用上述 7 月 31 日完整源码重新编译，使用早期 Docker 运行环境、原版参数、独立空数据库和相同飞牛宿主机出口运行。源码内的协议、QR、保活逻辑未改；旧版没有生产鉴权，测试入口仅监听宿主机回环，经本地 SSH 命令通道访问。没有挂载生产数据库，未替换正式账号。

这证明旧 `_auth` 路径、取票据及旧握手在这份新授权的首次调用中可用。它不是后台自然续期；相同 token 和本地期限前移不能作为服务端续期证据。

保留原版每 30 分钟检查、提前 45 分钟的策略；外部观察默认只读数据库和私有日志。计划在初始期限 18:10:44 及再过一个原始有效期之后分别做一次真实取码，记录调用本身是否刷新凭据、换票据或重建会话，避免把按需恢复记为后台续期。两次检查只是跨期限可用性对照，不代表 30 天保活。

若首先出现后台刷新失败或业务拒绝，则保留首次完整私有现场并停止测试容器，不重扫、不重放历史材料；最迟 21:10:44 结束本轮。正式服务保持原版本；此阶段尚未据此合并协议修改或宣称长期问题已修复。

## H5 / 公众号授权与本轮续期分开判断

用户随后反馈 H5 授权有问题。核对路由并以虚构公众号参数向独立测试实例提交 `/wx/oauth`，实测 HTTP 404：7 月 31 日的这份原始代码尚无该入口，这个请求未进入任何上游授权流程，也没有改变测试账号。

公众号 URL 生成于 8 月 6 日加入；曾有的自动取码尝试于 8 月 7 日从公开版本撤下。当前正式接口 `internal/httpapi/oauth.go` 只执行 `oauth.Build`，返回 `mode=authorization_url`、`authorization_required=true` 和 `code=null`，没有执行自动网页确认或兑换目标业务登录态。这是当前实现范围，不是从账号 alive 或续期日志即可推导可用的功能。

此前已独立复现 A8Key 到网页授权确认回调的关键流程，见[公众号协议评审](oauth-a8key-review.md)。另外的命令1254补丁属于不同候选，仍需严格校验响应、回调与 state，不能直接套用小程序 wx.login。尚需核对本次实际 H5 入口、目标授权参数和失败阶段；没有对正在观察的旧版账号追加 H5 真实授权请求。

### 用户明确要求并行对比后的 H5 实验（16:28）

用户随后明确要求一边观察旧版续期，一边引入近期 H5 实现做对比。已用当前传输代码和上述原会话的只读快照进行 `控制取码 → 1254 → 控制取码 → A8Key / 网页确认 → 控制取码`。两种 H5 路径均得到业务0、32位code及匹配回调 / 随机state；三次控制取码均成功。身份、凭据、登录票据和数据库会话前后不变，未建立新握手、未刷新主凭据，未访问业务回调。

这一实验说明旧会话可以承载新的 H5 授权请求；原路由缺失或仅生成 URL 并不等于协议不能取网页 code。当前正式接口尚未接入这次对照实现。原续期观察继续保留，但本轮已有显式额外业务请求，不能再称纯粹无干预样本。详情和复现工具见[早期会话与 H5 对照](h5-legacy-session-compare-20261031.md)。

### 本地页面访问中断与原会话复核（16:58）

页面打不开的原因是本地 SSH 转发进程仍监听端口，但底层连接已被重置。隔离容器仍在运行，未发生容器重启；已替换本地转发进程，加入断线后重新建连。仅在尚未转发 HTTP 内容的建通道阶段重试，途中断开的 HTTP 请求不重放。恢复后 `/health`、`/`、`/scan` 均返回 HTTP 200。

16:58:37 通过原会话只读快照额外做一次控制取码，返回32位code。该请求未触发 OAuth 刷新或新握手；身份、主凭据、登录票据和数据库会话均不变。使用审计工具的 `YYB_SESSION_CONTROL_ONLY=1` 单请求模式，没有重复 H5 实验。这是额外业务干预及当时的会话可用性证据，仍不是后台续期成功证据；原扫码和跨期限观察基准不变。

### 页面操作后的期限延长（17:06）

17:06:59 只读观察发现本地凭据期限变为19:06:15，刷新时间为17:06:15，access / refresh 与初始基准均不变，没有后台续期或失败日志。安全访问时间线显示17:05有取码、手机号请求，17:06:15有 `/accounts/refresh`。这属于页面触发的强制刷新，不能计作后台自动续期；也不能只凭相同token和默认两小时计时认定服务端有效期已延长。

继续保留原扫码、18:10:44及20:10:44的跨期限检查和21:10:44停止时限，但后续结果须注明这次手动刷新干预。完整原始访问记录不公开。

### 首次跨原始期限检查（18:13）

18:13:21 越过原扫码期限18:10:44后，观察工具按计划只调用一次原版 `/wxapp/getCode`，HTTP200、32位code；本次请求前后的token、登录票据、本地凭据期限及会话均不变。尚无后台 `credentials renewed` 或失败日志，不能记作自动续期通过。

此前18:04:28凭据刷新时间已前移、本地期限变为20:04:28，access / refresh 仍与扫码基准相同；访问日志显示18:04:29完成过额外 `/wxapp/getCode`。旧版取码的缓存重建路径会强制刷新凭据，因此这次先前业务请求及按需刷新必须保留在时间线里，不可把18:13成功记为纯后台续期或未经干预的原授权自然跨期。没有再次重扫，第二次20:10:44后的预定检查及21:10:44截止不变。

19:13只读发现又一次业务调用干预：访问日志19:07:23完成 `/wxapp/getCode`，保存的凭据刷新时间为19:07:22、本地期限变21:07:22；access / refresh仍与初始基准相同，后台续期及失败日志均为空。观察工具本轮没有追加业务请求。继续保留全部按需刷新时间线，不把期限反复前移当成后台续期，第二次预定检查和停止时限不延后。

### 本轮结束：两次跨原期限取码通过，后台续期未获验证（20:13）

20:13:21–22完成第二次预定 `/wxapp/getCode`，HTTP200、32位code。扫码仍为16:10:44，距本次成功约4小时3分钟，access / refresh与初始基准均不变；但这次请求自身改变了登录票据、协议会话及本地凭据期限，刷新时间变为20:13:21、本地期限变22:13:21。因此这次成功应记为旧版按需刷新 / 重建后的取码成功，不能冒充后台自动续期。

本轮后台 `credentials renewed` 和刷新失败日志均为0，已验证自然后台续期轮数仍为0。多次额外业务请求及页面刷新推后了本地期限，不能忽略这些干预并宣称“原授权无干预续期两轮”。本轮没有证据证明新旧差异的唯一原因，也没有验证30天保活。

观察工具以 `two_expiry_checks_completed` 结束并停止独立测试容器，随后只读确认容器为 `exited`；定时跟进已删除，不重启容器继续请求。私有基准、每轮记录、原始响应和日志保留，正式服务与正式账号未改动。测试页面随实验容器停止而不可用属于本次计划收尾，并非新一次账号失效。

可复用候选已收窄为旧 `_auth` 刷新及保存票据 / 重建链路；本次提供的是该组合在这份授权上的约4小时业务可用性与按需恢复证据。尚不满足“后台续期已明确”的条件，因此未将完整旧实现替换至正式版本，也未重新引入其宽松响应解析和本地默认期限假成功问题。
