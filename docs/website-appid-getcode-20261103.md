# 网站应用 AppID 取码与授权失效（2026-11-03）

状态：两组观察，没有隔离全部变量。能说的是：**对网站应用 AppID `wx5cd60c5d4817a188`（腾讯电脑管家）取一次码，授权的 OAuth 层随后被拒；对小程序取码没有这个现象。** 不能说的是机制是什么，也不能说所有非小程序 AppID 都会这样。v0.2.63 据此默认拒绝已知的网站应用 AppID，其余保护不变。

## 1. 生产里的两个账号

11-03 00:19 的夜间批量已被青龙错开（`RandomDelay` 约 30 分钟），运行 v0.2.61。批量里有一个脚本（腾讯电脑管家）用网站应用 AppID `wx5cd60c5d4817a188` 向每个账号取码一次，按账号顺序轮询：

| 时间 | 账号 | 这次请求 | 之后 |
| --- | --- | --- | --- |
| 00:27:39 | 1 | 到达上游，失败，没有拒绝码 | 00:28:05 起所有请求 `shortlink_application -14`；00:44 取票据后 `refresh_token -109`、`check_login -109` |
| 00:27:51 | 2 | 被本地熔断延后，没到上游 | 存活 |
| 00:28:20 | 4 | 到达上游，失败，没有拒绝码 | 00:29:31 取票据后 `refresh_token -109`、`check_login -109` |
| 00:28:35、00:28:47、00:30:32 | 6、9、17 | 被本地熔断延后，没到上游 | 存活 |

- 账号 1、4 在这次请求前一两分钟还在正常取小程序的码，请求后立刻失效；到达上游的两个账号都失效，被本地拦住的四个都存活。
- 自 11-02 09:00 日志开始记录 `app_id` 以来，这个 AppID 共 14 次取码，全部失败，没有一次拿到 code。
- 更早的夜晚日志没有 `app_id`，无法回查；11-02 00:19 失效的账号 1 和 18 当时的请求无法确认。

## 2. 备用号上的对照

用本机独立实例、新扫的一次性授权，同一流程：扫码，三分钟后只发一个取码请求，三十秒后只做一次刷新探测，期间没有别的刷新。

| 授权 | 取码请求 | 探测 |
| --- | --- | --- |
| 全新微信 | 一次 `wx5cd60c5d4817a188`：登录成功，应用层回 `wx.login returned no code` | 36 秒后 `refresh_token -109`、`check_login -109`，OAuth 层已死 |
| 用过的备用微信 | 一次小程序 AppID：拿到 code | 37 秒后续期成功，存活 |

这是一对一的结果。换号互换 AppID 的第二轮和空白对照另外记录。实验第一轮的探测脚本多刷新了几次，那一轮结果混杂，不引用。

## 3. 没有解决的问题

- 机制未知：上游为什么在这次失败请求之后拒绝 OAuth 层。
- 京东网页登录护照 `wx2f5d8f9715c59d10` 同属网站应用，也从未返回过 code，但没有单独试过；v0.2.63 把它一并默认拒绝，是因为它拿不到 code，拒绝没有代价。
- 10-03 的夜里这个 AppID 曾对账号 1 到 4 返回过 code，对方后端也接受了。当时账号没有因此失效。现在的现象可能还取决于账号或上游的状态。
- 其他非小程序 AppID 是否同样危险，没有数据。

## 4. v0.2.63 做了什么

- 取码请求（`/wxapp/getCode`、`/wx/code`、`/integration/actions/get-code`）带着已知网站应用 AppID 时，服务端直接返回 `403`，请求不发往上游、不占限速槽位、不进熔断计数，日志记为 `protocol.appid_denied`。其他请求（取号、operateWxData）不受影响。
- `YYB_CODE_ALLOW_APPIDS` 放行指定 AppID（优先级最高），`YYB_CODE_DENY_APPIDS` 追加自己的禁用名单，逗号或空格分隔，大小写不敏感。
- 熔断、登录预算、限速都没有改动。

## 5. 对脚本的影响

使用这两个 AppID 的脚本（例如青龙里的“腾讯电脑管家_code版”）会在每个账号上得到一条 `403` 和说明，不再把账号打死；它们本来也拿不到 code。要继续使用，设置 `YYB_CODE_ALLOW_APPIDS`，风险自负。

**脚本自己也默认停用（v0.2.74 起）：** 项目自带的 `腾讯电脑管家_code版.py` 和 `京东CK采集_code版.py` 现在默认不运行，打印原因后退出，不发任何请求，因为脚本和服务端是分开更新的，旧版本服务上它们仍会把账号打死。确认要运行，设置环境变量 `YYB_ALLOW_WEBSITE_APPID=1`，并在服务端放行（`YYB_CODE_ALLOW_APPIDS`）。已经把这两个任务加进青龙的用户，更新脚本后它们会静默结束。公众号网页授权的 code 另有专用接口 `/wx/h5code`（v0.2.66，见 [公众号网页授权 code](h5-oauth-code.md)）；这两个脚本改走它能否拿到可用的登录态没有验证，所以这里只是停用，没有改写。
