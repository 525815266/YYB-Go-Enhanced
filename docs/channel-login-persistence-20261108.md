## QQ：官方登录与设备桥接是两步

QQ 浏览器 22.3.7007.400 的官方“文件工具”扩展 4.0.1 中：

```text
POST https://kde.qq.com/trpc.ad.wx_oauth_svr.WxOauthHttpSvr/GetWxLoginBuffer
access_token = chrome.account.getLoginInfo 的 ctk（微信模式 3）
user_id      = 原生 getGuid() 的机器 ID
guid         = getFavSyncGuid()，允许空串
appid        = wx0dbc1ae97f156c38
header       = x-qbrn-cookie（QIMEI36、GUID、机器标识、浏览器版本）
```

原生 schema 另有 `chrome.qbExternal.getGuid(callback)`、`getFavSyncGuid(callback)`、`getQ16(callback)`、`getVersion(callback)`。旧桥接只读同步上下文，又强制要求可空 GUID，用户官方扫码后仍在推送前被拦截。v0.2.93 补上异步 API 调用，但 schema 存在不代表该扩展能获得权限；本机后续实测未开放这些异步方法，不能把此补丁视为根因已修复。

用户手动扫码后仍报告“缺少原生机器标识”，重新加载后又报告按钮“没有反应”。扩展 1.2.0 的真实独立复核确认：同一未登录官方 QQ 浏览器中，第三方扩展页同步 `getGuid/getFavSyncGuid/getQ16` 函数存在但返回 `undefined`，`chrome.qbExternal` 方法未开放；官方公共小游戏页却可读取原生机器标识。`chrome.environment.getMachineGuid` 也能返回值，但与原生 `getGuid` 实测不同，不能替代。

因此 1.2.0 临时创建后台 `https://pcgame.qqbrowser.qq.com/main` 标签，通过 `chrome.scripting.executeScript` 的 MAIN world 只读设备参数，校验三处 origin，完成或超时后关闭自己创建的标签。账号 ctk 由扩展后台单独读取，不进入该网页；不伪装官方扩展 ID、不修改浏览器权限白名单。周期转发复用设备缓存，手动推送重新读取；并发请求不重复换票。

设置页显示扩展版本及即时进度，禁重复点击，明确处理存储失败、后台消息失败、无结果、设备页超时、网络与响应体超时。后台现在返回最终成功／错误状态，避免旧版只返回 `done` 导致页面仍显示旧提示。请求拒绝重定向，状态不保存原始服务端响应。

真实官方浏览器的 MAIN 设备读取、原标签保留、临时标签关闭和设置页输入错误反馈已通过；虚构账号回归覆盖消息与推送。但尚无本轮用户真实推送成功结果，因此不能称 QQ 扫码、电脑快速登录、取码和持久化全部接通。回环测试地址只指当前电脑，飞牛需实际 NAS 地址。更新扩展需在管理页重新加载，F5 可能仍使用旧 service worker；已有登录无需重扫。扩展独立版本 1.2.0 兼容服务端 v0.2.93，本次不重启飞牛服务。

官方调用直接消费 `login_buffer`。本项目允许省略默认零业务码，但仍校验完整 protobuf 票据及宿主 appid；显式非零、null、字符串业务码和错误票据均拒绝。按浏览器账号区分导入身份，防止同一机器不同微信互相覆盖。

每 30 分钟推送只是转发由浏览器维护的 ctk，不是服务器刷新协议。“换票已保存”也不等于 wx.login 已返回 code，更不等于长期保活。

## 手游助手：访问刷新计划不等于授权总寿命

旧解析先补 30 天，且 JSON 已含 token 时跳过 cookie，可能遗漏 cookie 的 `expires_in`，延迟后台调度。本次先读取全部来源，完全无期限才用两小时计划；明确已过期时间不改为未来。保存 `upstream/fallback` 来源，历史无标记的 30 天值按原发放时刻修正调度，不从当前时间重新起算。这不代表旧 token 的真实服务端期限已获证明。

飞牛只读匿名时间线（北京时间）：一个样本 11 月 8 日 09:00:14 业务成功，09:03:14 的 syzs refresh_token/check_login 均报 `-109`；保留的结构化记录不足以确认其底层微信拒绝码。另两个 11 月 5 日傍晚建立的样本在 11 月 8 日中午仍业务成功，超过 64 小时；存在按需恢复和 `-14`，不能称无干预样本。既不能推定统一一天上限，也不能把调度缺陷当作所有失效的唯一根因。

此前只保留 type 1 Access PSK，丢弃 type 2 Refresh PSK。现分别保存并验证 SQLite 重载；type 2 不用于 Access 0-RTT。长连接 Refresh PSK 恢复握手尚未实现，旧会话中从未保存的密钥也无法凭空补回。

## 停止假续期及拒绝重放

旧 QQ 刷新仅换票后本地加一天；雷电没有刷新请求也本地加七天。现在自动调度跳过两者伪刷新，不记 renewed、不因此写回 alive；手动刷新明确返回不支持，界面显示期限未知。

雷电 ManualAuth 明确 `-10` 后 CAS 清理已拒绝凭据／票据；有独立可复用会话保留 `session_only`，否则过期，保留首次 typed 错误。恢复换票若仍得到同张已拒绝票据，不再登录第二遍。网络错误不一概当成撤销。

## 验证与升级边界

- 合成官方 API 回归覆盖同步／异步、空 GUID、缺机器 ID、错误 token 别名和两份桥接文件一致性，不访问真实登录态。
- 扩展回归覆盖按钮即时反馈／禁重复、存储与消息失败、无响应／超时、请求及响应体超时、并发共用、缓存设备、ctk 不落扩展存储、拒绝错误 origin 和清理临时标签（含迟到创建）。真实设备脚本使用全新未登录官方 QQ 配置，仅访问公共页，无真实账号和上游换票。
- Go 回归覆盖 cookie 寿命、过期时间、历史调度与期限来源、QQ 设备参数和票据校验、假续期零请求／零状态回写、雷电不重放、两种 PSK 数据库保存与重载。
- 独立服务的桌面／手机扫码页使用虚构二维码，不触发上游扫码或业务请求。
- 升级保留账号、数据挂载、端口、令牌和安全配置；不自动重扫或重放已拒绝密钥。升级不保证旧失效授权恢复。
