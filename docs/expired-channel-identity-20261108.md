# 失效授权被误显示为 YYB（2026-11-08）

## 现象与原因

多渠道账号的雷电授权原本已在组内。上游明确拒绝授权后，服务清空登录票据和凭据，连同 `provider=ldplayer` 一并清掉；旧 `AccountPublic.ScanProduct` 仅从凭据标记识别雷电，因此原记录改显示为“YYB · 已失效”。这一次现场的账号创建时间早于失效时间，身份仍带 `ldplayer:` 前缀，账号 ID、归组均未变化，能够确认是原雷电记录被错标，并非后台新增了一份 YYB 授权。

清理函数 `keepChannelMarkers` 当时只保留手游助手标记；QQ 浏览器和电脑管家同样未覆盖。事件落库白名单也遗漏了雷电和 QQ 浏览器，导致它们的扫码事件渠道为空，失效后又可能记成 YYB，影响排查。

## 修复与升级行为

- 清理被拒绝的凭据时，仅保留已知渠道的非敏感 provider 标记；token、票据及嵌套原生凭据照常删除。
- `WechatAccount.ScanProduct()` 统一账号列表、协议路由和账号事件的渠道识别。已有 `pcmgr:`、`qbbrowser:`、`ldplayer:` 身份前缀能恢复历史记录的渠道显示；不读取或重放旧凭据，不写回数据库。
- 保留 ID、归组、配置和原失效状态。失效雷电记录仍需重新授权才能使用；本修复不代表雷电持久化或长期保活已经解决。
- 无标记且无专属前缀的历史记录无法可靠区分手游助手和 YYB，不按昵称、头像或猜测改写。既有错误日志保持原样，新事件使用修复后的渠道。

## 回归验证

以虚构数据复现旧版失败，再验证四个非默认渠道的自动过期、仅保留会话、手动过期，以及 SQLite 关闭重开。检查只留下渠道标记、秘密被清除、归组不变。

账号接口回归覆盖“有效 YYB 主账号 + 历史已清空凭据的失效雷电成员”：默认只列一个主账号；控制台完整列表保留两个原 ID，分别显示 YYB 和雷电，读取不创建或激活授权。协议 provider 和新日志分类另有回归。
