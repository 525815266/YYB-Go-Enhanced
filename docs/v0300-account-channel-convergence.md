# v0.3.0 账号、渠道与 issue 收敛

## 已确认的缺陷

控制台补扫曾使用两个请求：普通 QR 确认先新增账号，浏览器随后调用 fleet bind。身份核验失败、网络断开或页面关闭都可能留下未归组的新账号。已有账号入口现在直接创建锚定原主账号的多渠道更新链接，复用服务端现有事务；失败停止，不能退回普通新增流程。

每个协议渠道仍有内部成员 ID，用于会话、代理和日志隔离。`/accounts`、`/integration/accounts` 默认固定返回主 ID 及身份，status 汇总组内可用状态，不改数据库；`include_members=1` 才返回各成员及其真实状态。外部脚本应使用主 ID。直接以成员 ID 或 OpenID 请求协议返回 HTTP 409，`data.member_ref_not_allowed=true`，`data.primary_ref` 指向主账号；主账号请求内部仍可分配给成员。集成取码入口也遵守同一规则。管理、更新、熔断和代理配置保留逐成员操作。

雷电没有可跨渠道核验的 unionid，票据派生的 `ldplayer:` 身份每次扫码都可能改变。QQ 浏览器返回自己的微信身份值，其与其他宿主是否属于同一开放平台身份域尚无充分依据。现在只有涉及 QQ/雷电的关系可由授权人明确确认同一微信后关联；不自动按昵称绑定，不伪造 unionid。同渠道真实身份冲突仍拒绝。失效雷电成员可在确认后换新票据，事务内复用原 ID、备注、配置，清理旧会话；活跃不同授权不被静默替换。

熔断总控实际已经优先于账号偏好，旧 UI 却直接展示 account_enabled。现在复选框展示 effective，总控关闭时禁用并显示保留的偏好。其他标签页收到保存通知、窗口重新获得焦点时重读；没有改成批量覆盖账号偏好。

#155 确认 HTML 缺少缓存限制。模板服务、扫码直写路径和缺失模板回退统一 `Cache-Control: no-store`，静态资源策略保持独立。新响应头不能主动清除客户端已有的旧 HTML，升级后若仍命中此前缓存，需首次强制刷新。测试覆盖各页面及 fallback 响应。

## 雷电掉线的新证据和改动边界

2026-11-08 对飞牛数据库及保留事件仅做只读核查，业务请求 0。两份近期雷电授权分别在扫码后约 25 分钟、59 分钟的首次保留协议请求中返回 `manual_auth -10`，从最近扫码至该失败没有成功取码事件。较早同 ID 的历史不算本次授权寿命。不能称这两份授权已经持续成功使用后掉线，也不能据此确定票据固定有效期。

源码确认扫码只保存 login_buffer，第一次业务请求才做 ManualAuth。雷电不能复用 YYB OAuth 刷新端点，该延迟会把短效/一次性票据留到业务时才尝试。新确认流程在账号归属与最终代理落库后立即建立协议会话，成功仅记录 `account.session_prepared`；没有额外请求业务 code，不伪造期限或 renewed。明确 -10 保存 expired 并清票据，其他失败 unknown；原授权快照条件阻止旧请求覆盖新扫码。不会主动消费旧的正式票据。

这项修复尚缺新扫码的真实端到端验收，不能等同长期续期。此前官方 SDK 的隔离 AutoLogin 返回 1/-13，Go AutoAuth 拒绝与缓存 -14 仍是未解决的恢复证据。长连接生命周期、官方正常关闭、Refresh PSK 恢复握手仍须分别验证，详见 [原雷电审计](ldplayer-channel-audit-20261105.md)。

## Issue 错误诊断

#147 的本地 UIN 精度缺陷已在 v0.2.92 修复，并包含在本版。#145/#142 的首次与缓存请求身份不一致已用临时数据库确定性复现，回归覆盖字节一致；仍需报告者确认真实手机号/operate 的全部现象。v0.2.35 也有普通 JSON 解码缺陷，不能用它解释所有版本或平台差异。

#136 的明确业务 ret 曾被取码函数丢弃，因为只查看 f2.f3 的 code。现按固定 envelope.field2.JSLoginResponse 路径读取 BaseResponse.field1.ret 和 JSAPIResult.field1.code，分别返回 `jslogin_business`、`jslogin_result`；字段定义参考 [JSLoginResponse](https://github.com/sbgayhub/golem/blob/7d75a9ee1542a45ab216cdb411bf38981b4e4763/host/api/miniapp/miniapp_api.proto)，不是声称该仓库能证明本项目全部真实回包。严格拒绝相关字段的重复、截断和错误 wire，不递归搜任意 32 字节，也不输出上游 errmsg 或原始 protobuf。显式拒绝与空 code、外层 shortlink -14、凭据过期分开，保留会话和凭据，不强刷/重放/学习全局 AppID 封禁。

H5 的明确业务拒绝补 `h5_oauth_business` 诊断。#141 的外层 shortlink -14 与 H5 内层 ret 是不同阶段；缺少目标及真实验收，不能称所有公众号授权已修复。`-12028` 的服务端含义尚不明确，本次不猜测为封号、AppID 限制或渠道必然不支持。
