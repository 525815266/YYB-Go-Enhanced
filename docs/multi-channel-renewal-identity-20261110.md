# 网页版多渠道扫码续期核验修复

## 复现与根因

原主账号已经绑定电脑管家、手游助手、QQ 浏览器等成员时，多渠道更新页面仍先比较新授权与主账号的 UnionID，再查找组内原渠道成员。主账号资料缺少 UnionID、旧凭据失效，或者手游助手资料降级为不含 UnionID 的本地资料时，即使扫描者与原渠道 OpenID 完全一致，也会返回 409“微信身份无法核对”。旧版只有 QQ 浏览器／雷电有显式确认入口，电脑管家和手游助手因此卡在无法继续的错误状态。

这不是“已确认是不同微信”。跨渠道资料缺失不能用来否定组内已有的同渠道身份，也不能凭昵称、头像自动合并新授权。

## 修复规则

1. 在原主账号组内先查找同渠道记录。新扫码 OpenID 与原渠道相同，则原位更新原 ID，无需再取得主账号的 UnionID、刷新主凭据或要求重新关联。已失效成员也适用；资料接口失败或返回空字段时保留原资料和关联记录。
2. 新渠道的身份能够核对时自动归组；缺少核验字段时返回结构化确认提示，电脑管家、手游助手也能确认同一微信后继续使用当前二维码。未确认前不写账号、不新增 ID、不激活会话。
3. 已有同渠道 OpenID 不同仍拒绝；同一可比较身份范围内的 UnionID 明确不同仍拒绝。QQ 浏览器和雷电延续原有跨身份范围的显式确认规则；失效雷电变更票据仍仅能在明确确认后复用原成员 ID。
4. 原链接归属检查、原基础账号 OpenID／主账号锚点的事务检查、账号授权快照检查以及重复确认的幂等处理保留。从组内子账号创建的更新链接依赖原有归组和事务锚点，不再重复要求跨渠道资料。

## 页面与升级

需要确认的卡片显示“微信已授权，无需重新扫码”，移除已消费二维码图像并显示继续关联按钮。明确身份冲突仍显示错误，按钮不能覆盖其他微信。静态资源版本同步更新。

有效期内的更新链接、已保存的账号、成员 ID 和设置在升级后保留。尚未保存的二维码会话在内存中，服务重启后不能继续使用，需刷新更新页面重新生成二维码。不要通过删除原账号或新建独立账号来规避核验。

## 验证范围

合成数据先复现旧版失败，再验证五个渠道的有效／仅会话／已失效成员原位更新、从子账号创建链接、缺字段的同二维码确认、资料失败时保留身份、重复确认及明确冲突拒绝。浏览器回归使用独立测试库和模拟扫码响应，不调用真实微信授权或商户业务。

本修复解决扫码更新与归组核验，不修改协议保活算法，也不宣称各渠道长期自动恢复已经通过验证。没有把真实身份、凭据、二维码或私有日志写入本说明。
