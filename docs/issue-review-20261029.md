# 新反馈复核与接口测试区（v0.2.50）

本轮查看开放 issue 及近期已关闭帖的新回复。#105 / #112 提供了足以修正本地恢复策略的对照；#109 / #111 的应用类型线索仍需具体 AppID、请求入口及业务阶段验证，不凭评论推定全部非小程序接口已失效。

## 有帮助的证据

| Issue | 观察 | 本轮处理 |
| --- | --- | --- |
| #105 | 同一授权、固定出口下，应用 `-14` 后仍有成功取码；另一次则进入 ManualAuth / OAuth 恢复并清空账号 | 单独应用拒绝不再自动重建共享会话或触发账号恢复 |
| #112 | `getCode` 成功与 `operateWxData` 409 相隔很近；恢复链首项为应用 `-14`，之后才是 refresh / check-login 拒绝 | 同一保护覆盖取码与通用转发；补充 502 阶段诊断 |
| #110 | 已失效记录返回 409，`upstream_errors=[]` | 说明是已失效快拒绝，不能重建首次原因；需要第一次错误和时间线 |
| #109 | 报告目标为原生 APP 授权 AppID，询问非小程序通道 | 请求具体 AppID、调用接口及应用类型；测试区明确 js-login 与 OpenSDK / OAuth 不同 |
| #111 | 微信取码和取手机号 code 成功，业务后端返回 `7005` | 区分微信能力与业务登录，等待目标脚本、字段结构及业务请求；不据此归因代理或某类 AppID |

#105 的 37 分钟静默不能证明前一次调用留下延迟影响，也不能证明后一次独自撤销了 OAuth。#112 的相邻请求不能确定上游拒绝原因。两份日志共同确认的是：一次应用层拒绝不足以判定共享账号失效，而旧代码可能因此启动账号级恢复。

## 最小修复边界

已认证短连接仅返回应用层 `-14` 时，当前请求仍失败并返回 HTTP 502；保留原会话、凭据、扫码时间和到期时间，不自动重建、取新票据或强制轮换。混合传输 / ManualAuth / OAuth 错误不属于这一保护；真实授权拒绝仍走原有判断，后台定时续期策略未改。

502 中的 `data.upstream_errors` 只提取类型化错误的阶段和数值码。`request_rejected=true` 表示当前应用请求被拒绝且没有触发账号级恢复；不是业务成功，也不保证另一条并发请求或后台刷新不会改变账号状态。已经失效记录的 409 不会为补日志重新请求上游，不虚构旧错误。

这不是完整的分层状态改造，尤其没有解决后台 OAuth 拒绝时仍有效的 ILink 会话如何保留的问题；也不能恢复已清空 / 已撤销的授权。快速失效与长期自然续期仍未确认解决。

## 测试命令按当前渠道生成

公开 `/wx/*`、`/wxapp/*` 路由保持兼容；服务端从所选账号判断 YYB / PCMgr，不要求脚本额外传产品参数。二维码生成例外，它尚无账号授权，需要指定或采用默认产品。

控制台按小程序、渠道账号、未验证兼容转发、公众号链接分组；显示当前渠道，手机号入口分别标记 PCMgr `1141` 与 YYB 兼容 `1020`。资料入口也说明 PCMgr 读取已保存扫码资料。仅公开已验证范围，不用一个目标的成功推广所有能力。

展开“测试命令”后，可选择 Bash cURL / PowerShell 并复制。示例跟随访问的域名 / IP、当前账号、路由、AppID 和 JSON，实际网页调用与命令共用参数构造。命令只引用 `YYB_PROTOCOL_TOKEN` 环境变量，不复制页面令牌。JSON 无效或缺少必要参数时禁用命令复制。

`getCode` 是小程序 js-login；原生 APP OpenSDK 未实现；`oauth` 正式入口仅生成授权 URL。#75 先前隔离 A8Key 授权实验的成功证据仍保留，不能把“正式接口未接入”改写成“协议从未验证成功”。PCMgr 原生存在独立 `5112` / `4744` 路径，见[原生对照](pcmgr-api-paths-20261029.md)，不把它们当作已上线的通用转发。

- `go test ./...`、`go vet ./...`、`protocolaudit` 标签编译和测试通过；新的回归覆盖应用拒绝不重试、不清理、保留诊断、其他目标继续可用，以及混合错误不被保护规则吞掉。

- 原工作台、扫码切换、合并账号与测试结果不跳顶的回归通过。没有故意在生产制造 `-14` 或撤销有效授权，自动化回归不能替代用户原场景复测。
