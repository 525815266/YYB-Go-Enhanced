# 授权与缓存会话分层（v0.2.55）

此前真实对照观察到 OAuth `-109 / 42007` 后，同一 ILink 缓存会话仍能取码。旧版将两层一起清空，造成仍能工作的协议会话也停止使用。v0.2.50 保护单独应用 `-14`，v0.2.51 继续修正 OAuth 拒绝后的处理。

| 状态 | 含义 | 后续行为 |
| --- | --- | --- |
| `alive` | 已保存授权可继续使用 | 沿用按需调用和后台续期 |
| `unknown` | 暂时失败或未能确认 | 保留原有重试判断 |
| `session_only` | 授权被明确拒绝，但当前协议出口仍有可解析 PSK 或独立原生恢复材料 | 清除 token / 登录票据，停止旧凭据续期；尝试协议缓存或 AutoAuth，仍提示补授权 |
| `expired` | 没有可继续使用的会话，或用户手动标失效 | 清理凭据及缓存，要求重新扫码 |

“存在缓存”只表示本地仍有资格尝试，不证明服务端接受；缓存请求成功也只证明当次请求。`session_only` 不显示“可用”，不展示授权倒计时，不能手动点“仍有效”改回正常。成功补扫会按原规则替换授权，原账号 ID 及配置保留。

授权拒绝时只检查当前配置协议出口的缓存；仅在原设置允许时检查直连缓存，不跨账号或任意网络复用。保留真实 PSK 期限，不延长到期、不修改扫码时间、不恢复历史失效账号。无缓存时沿用原有失效处理。

受限模式不使用拒绝的 token / buffer，不建立新的 ManualAuth，不因失败重放业务。v0.2.52 可使用原授权保存的 AutoKey / EncKey 独立恢复 ILink，轮换只写协议会话，不改 OAuth、扫码时间或账号状态。没有可用材料时首次调用转为失效。用户手动失效 / 删除账号会清理缓存，不能因这项兼容继续调用。

v0.2.51 还修补代理允许直连回退的路径：应用 `-14` 直接返回，不先删代理会话或改出口。其他路由策略保持原设置。

## 取码卡在旧会话的恢复

真实对照发现另一个边界：当前 PCMgr 授权仍能取新票据，但旧协议会话持续返回 `-14`。v0.2.50 的保护阻止了误清理，也让这类可恢复请求一直停在旧缓存。不能因为存在这一例子，就将所有 `-14` 直接视为授权失效。

v0.2.51 只对 `wx.login` 增加候选验证：保持原缓存，按原账号凭据出口取新票据、按原协议出口建候选会话，用相同 AppID 验证；拿到非空 code 后才按授权快照原子写回。失败保留旧会话和首次错误，不进入 OAuth 恢复。每账号 / 出口 5 分钟最多发起一次；更换授权后使用新快照。手机号及任意数据业务不参与重放；`session_only` / 已失效账号禁止这个步骤。

以上描述是 v0.2.51 的实现。v0.2.55 将正常授权改回保存票据优先；ManualAuth `-10` 后取新票据，只有新票据接口明确 access 拒绝才进入一次凭据刷新，成功提交顺序和 CAS 保护保留。失败按账号 / 出口 / AppID 退避，成功解除。`session_only` 不使用被拒的主凭据。详见[恢复顺序与边界](code-recovery-20261031.md)。

2026-10-29 飞牛 ID1 的只读私有副本实测：

| 步骤 | 结果 |
| --- | --- |
| 保存的原会话取控制 AppID 的 code | 应用 `-14`，code 为空 |
| 原凭据取新票据，候选会话验证同一 AppID | 成功，code 长度 32；只请求一次新票据 |
| 再从隔离数据库复用替换后的会话 | 成功，code 长度 32 |
| 授权及扫码时间 | 不变；未请求 key 轮换、未写生产数据库 |

这证明了当前可恢复的缓存失败，不证明旧会话被拒的具体原因，也不是 OAuth 自然续期。此前本机研究有额外会话握手，不能把这个样本称为无干预观察。

可选复核：显式提供当前有效 PCMgr 私有快照后运行 `TestPCMgrCodeRecoveryAudit`（`protocolaudit` 构建）；没有输入默认跳过。真实旧缓存未复现 `-14` 时测试直接停止，不将它记录为恢复成功。输入必须留在忽略目录，不能提交实际账号材料。

回归覆盖模拟 OAuth 拒绝、原会话保留、旧凭据清除、扫码时间不变、后续缓存操作、拒绝后不重复续期、缓存缺失终止、手动失效清理和代理回退。模拟状态转换不是上游长期续期证据。生产验证只使用当前有效账号的有限真实调用，不故意撤销授权或伪造到期。
