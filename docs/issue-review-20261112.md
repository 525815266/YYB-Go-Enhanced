# 2026-11-12 issue 复核

本轮以 main 的 v0.3.4 为基线，检查 13 个未关闭 issue。修复本地可确认的问题，不将未复现的上游限制或长期续期标成成功。

## #166：压缩 ID 的归属唯一键冲突

账号在 YYB SQLite，用户归属在独立认证库。旧删除入口只删账号，未删认证库的 `account_owners`。例如原 ID 1/2/3 分别已有归属，删除账号 1 后压缩为 2→1、3→2，虽然现有迁移用负 ID 避免链式碰撞，归属行 1 仍会占用目标位置，触发报告中的唯一键冲突。

修复在归属迁移事务中使用完整压缩前账号列表清理孤立归属，校验目标不重复后迁移。正常账号的归属及未归属状态均保留，不以 `REPLACE` 或忽略冲突覆盖真实归属。预览不写库。后续删除同时移除归属，账号删除失败时恢复归属；压缩账号库失败后的逆向归属迁移使用独立超时上下文，不继承已取消的请求。回滚失败明确报错。

临时 SQLite 测试覆盖两个用户、历史目标占位、负数残留、链式映射、逆映射、未改 ID 的正常账号、未归属账号、非法映射拒绝、迁移事务失败回滚、删除和 ID 复用、删除失败恢复归属。认证库 MySQL 分支共用迁移逻辑，本轮未连接真实 MySQL 验收。

升级前备份账号库和认证库。升级后通过界面预览并确认压缩，无需手工删除 `account_owners` 或重扫微信。两库操作仍依赖补偿回滚，不是分布式原子事务；账号整理期间避免同时扫码、删除或手工修改数据库。未托管的外部脚本仍需检查 ID 引用。

## #165：飞天 token 获取不等于有效登录

旧代码的 `decode` 仅发送一份内置固定 `context`。本次 YYB code 只用于另一个绑定请求及 Referer，未参与生成新的 context。故“code 绑定成功 → decode 返回 token”不能证明取得本账号的新会员会话；再用同一份 context 也不能刷新它。旧代码还直接缓存未验证 token、将验证网络失败当过期、在签到失败后继续活动并报账号成功。

本轮移除固定 context 和历史 code 兜底，支持按 YYB 账号条目配置本人 `LZ_XCX_DATA`；多账号禁止共用单个 context。只有 decode 成功且会员查询返回有效会员身份后才保存带新来源标记的缓存，并申请本次签到 code。旧缓存来源不可验证，不直接复用。明确失效清缓存；网络或未知响应保留缓存并停止；签到失败不重放、不执行活动、不计成功。

只读检查官方公开页面及 JS，确认 `xcx_decode` 使用 `context`，`getCurLoginUser` 使用 `userToken`。没有访问账号接口、消耗真实 code 或运行签到/抽奖。本轮是登录验证与失败处理修复，**尚未实现 YYB code 独立换飞天会员 token、context 自动获取或真实签到验收**；#165 保持待验收。使用者需在本地配置本人数据，不要上传凭据或完整响应。
