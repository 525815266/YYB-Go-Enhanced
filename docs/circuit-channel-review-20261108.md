# 熔断控制、扫码渠道与手游助手寿命复核

v0.2.95 实现 #149 的 UI 熔断控制，修正手游助手图标，并收敛 #138 与寿命证据。本轮未为正式账号追加取码、强刷或扫码；业务成功时间均来自已有只读日志。真实身份、凭据、code、设备标识及原始日志保持私有。

## 熔断开关

管理员在「个人设置 → 协议熔断总控」修改全局开关；用户在首页「调用配置」修改当前渠道账号。有效值为 `全局开启 && 账号开启`。全局关闭时仍能保存账号偏好，界面明确显示其暂不生效；全局开启后恢复按账号偏好执行。

未保存全局开关时采用 `YYB_CIRCUIT_BREAKER`，默认 on。SQLite 保存后优先于该默认，重启保留。账号开关未保存时默认开启。修改开关清除对应目标／会话层冷却计数，下次请求使用新设置；已发出的请求不被撤销。关闭期间不累计后续熔断失败。

全局仅管理员可管理，账号沿用现有归属权限，外部协议令牌无管理权限。账号配置使用带外键的表，删除清理、压缩 ID 迁移，合并授权保留目标配置，不因 ID 复用串到另一账号。内存冷却表由互斥锁保护，持久策略每次从数据库读取，无需无锁修改运行中的配置。

开关只控制连续 `-14`／空 code 的本地目标及会话熔断。独立限速、登录预算、AppID 名单及授权撤销处理各自执行，关闭后不保证上游成功，也不是保活修复。

## 手游助手不是统一 24 小时上限

2026-11-08 晚间对飞牛 SQLite 与结构化事件作只读复核，无新增业务请求：

| 匿名样本 | 观察到的事实 | 可得结论 |
| --- | --- | --- |
| A | 旧会话为 `session_only`，近期请求多次上游应用层 `-14`；另有本地熔断等待 | 现有会话不能完成这些业务，不能把上游拒绝归因为 UI 开关 |
| B | 19:06 重新扫码，19:08 恢复后取码成功 | 旧建档时间不能当本次连续授权起点，不能声称此授权已持续约 103 小时 |
| C | 11 月 5 日 18:54 建档，11 月 8 日 17:08 取码成功，间隔约 70.2 小时；保留日志中未见重新扫码 | 不支持统一 24 小时上限；含按需换票／恢复，不是纯后台自然保活样本 |
| D | 11 月 5 日 18:54 建档，11 月 8 日 16:41 取码成功，间隔约 69.8 小时；保留日志中未见重新扫码 | 同上，不能外推所有账号寿命 |

`created_at` 是账号建档时间，重扫更新原 ID 不会重置它；日志留存有边界，“未见重扫”不能当成无限期完整证明。`alive`、未来本地期限与 `keepalive.renewed` 本身也不是实际业务成功，更不是服务端 refresh token 总寿命证据。

现有实现已使用手游助手专线 `syzs_refresh_token`／`syzs_check_login`（业务 `syzslogin`），v0.2.93 已修 cookie 寿命读取及错误 30 天调度；本轮未发现新的可复现 24 小时定时失效代码。刷新 `-109` 是网关错误，应用层 `-14` 是业务拒绝，本地 `circuit_open` 是流控，三者应分开分析。type 2 Refresh PSK 已保存，长连接恢复握手尚未实现，部分账号拒绝原因仍待完整证据。不能宣称全部长期保活已解决。前序证据见[渠道持久化复核](channel-login-persistence-20261108.md)。

## #138 的其他扫码机制

本轮读取 #138 正文与评论，没有新增客户端或接口参数；评论中的 QQ 独立扫码更新已在 v0.2.94 实现。核对公开对照仓库 `ZHwin/yyb` 的 `yyb-py/app/app/pure_wxcode/wmpf.py`、`type5_auth.py`，最近修改仍为 `e1e9c3608d4008d24e0c23301ef4258cf2e11391`（2026-09-14），没有新的 scope 或签发机制可取代前次被拒的流程。本轮不重复已失败的上游请求。

新增静态线索：本机当前官方微信 **4.2.0.13** 的 `Weixin.dll` 含 `/cgi-bin/micromsg-bin/get_ilink_auth_code` 与 `/cgi-bin/micromsg-bin/mm_ilink_cloud_app_auth`，以及配套 `micromsg.GetILinkAuthCodeReq/Resp`、`micromsg.ILinkCloudAppAuthReq/Resp`、`ilink.IlinkAppAuthClientInfo`、`ilinkapp.ILinkAppAuthBuffer` 类型。主客户端已有 ILink 签发相关入口，可作为渠道 5 票据来源的候选继续追踪；**仅凭静态字符串尚未证明游戏中心使用它们，也未恢复 CGI ID、请求字段、微信会话签名或返回 buffer**。这些是微信已登录主客户端的 CGI 候选，不是可直接拿网站 OAuth token 调用的公开 HTTP API，不能拼 URL 后宣布渠道完成。

复现时仅读取官方安装二进制，不读取账号目录：

```powershell
python scripts/inspect_channel_artifacts.py 'C:/Program Files/Tencent/Weixin/4.2.0.13/Weixin.dll' --pattern 'get_ilink_auth_code|mm_ilink_cloud_app_auth|GetILinkAuthCode|ILinkCloudAppAuth|IlinkAppAuthClientInfo|ILinkAppAuthBuffer' --context 30
```
